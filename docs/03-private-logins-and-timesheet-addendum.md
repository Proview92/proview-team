## Private logins (10:50 to 11:05), owner asked for it ("number one, go ahead")
Server mode is now PRIVATE by default (`PRIVATE=0` env turns it off = old open mode, kept for tests).
- **Sign-in:** the app shows a name list (from `GET /api/people`, needs APP_CODE if set), then a PIN box. PIN is the existing `p.pin` field (3 to 6 numbers), the same PIN the kiosk uses. `POST /api/login {id,pin}` returns a random session token (90 days, kept in `db.sess` in the data file; sent as `x-token`). The client keeps it in localStorage `proview-token`, with `proview-me`. Wrong PINs: 8 per phone+person or 25 per person in 10 minutes = HTTP 429 for 10 minutes.
- **Bootstrapping:** the first phone on an empty server uploads its starting data (`/api/init`, no token needed, only when the server has no data). The Owner with no PIN creates one on the login screen (`/api/setpin`, allowed only for an owner whose PIN is empty). Everyone else with no PIN sees "ask your manager". Settings > Users has "Give everyone a PIN" (random 4 digits, unique, shows a copy list; skips owner and trial people) and a "No PIN yet" chip. Profile > "My PIN" lets a person change their own.
- **What each person receives** (server `viewState` / `viewOps`, applied to the full state, to the change feed and to snapshots): payslips = own, or all with the Payslips feature; entries = own, or all with Timesheets/Approvals (others' OPEN entries too if `perms.memWho`); leave and avail = own, or all with Time off/Rota; chat = only messages from, to or "all" for that person; notifs = own (no-`to` ones only for managers/admins); exports = Reports feature; payMap = Payslips feature; people = others lose pin, rate, email, phone, payNo, payName, contract, otp, code, invited (and docs unless manager/rota/timesheets, and then file data is blanked); managers with People see everything except an owner's or admin's PIN; own record is full. Items that stop being visible become deletes in the change feed, so a closed entry vanishes from others' "who is in".
- **What each person may change** (server `checkOps`; disallowed ops are silently dropped and the client re-syncs): owner/admin everything; managers only keys their feature switches cover (`WF` map); staff only their own entries/leave/avail (status can only be new or "pending", no self-approval), own chat, any notifs, tasks updates, shifts only if it is theirs or an open cover shift. A person's own record is accepted with role, feats, rate, locs, licensed, archived, g, sched, contract, earliest, flex, trial, noTrack, payNo, payName, start, otp, code and docs.ovr forced back to the stored values. Managers with People cannot change role or feats, cannot edit an owner/admin, new people are forced to role member.
- **Taking a cover shift:** the client sends a condition (`cond:[{k:'shifts',id,f:'pid',v:null}]`); the server answers HTTP 409 `conflict` if someone already took it, the client re-syncs and toasts "Someone else has just taken this shift." Tested: first wins, second gets 409.
- **Trial hand-over:** `POST /api/handover` (needs People feature, target must be a trial person) gives a 6-hour token for the trial person; the manager's token is kept in sessionStorage `proview-back` and restored after the person signs the pack (page reloads back to the manager). Trial people have no PIN, so they cannot sign in on their own phone unless a manager sets one.
- **Sign out** (private mode): pushes pending changes, logs out on the server, wipes the device's cached copy, reloads to the login screen. Kiosk: only offered to people with the Timesheets feature; the kiosk device stays signed in as a manager (needs everyone's PINs, which managers receive).
- **Tested** (real server, `/tmp/pv.py`, `/tmp/pv2.py`, `/tmp/pv3.py`): login, wrong PIN, owner setup, Duygu sees only her payslip and entries, others' pin/rate/email hidden, 5 of 6 tampering ops dropped (the sixth was sanitized), cover race 200 then 409, UI login/wrong PIN/sign-out, trial hand-over and return, manager view, change feed leaks nothing private.
- **Known limits:** manager visibility by group (mgrViewAll etc.) is screen-level only; PINs are stored as typed in the data file (protect backups); the login name list shows every name to anyone who has the URL and code; a second PIN-less owner cannot be created; legacy tests sy2/sy3 (access-code flows) were not re-run after this change; sy.py passes with PRIVATE=0.
