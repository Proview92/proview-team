## Roles and permissions (10:44)
- Roles: Owner, Admin (both always have every feature), Manager, Staff (member). `feat(p,k)` order: owner/admin true; a per-person override `p.feats[k]` wins; otherwise a manager gets `MGR_DEF`.
- **Changed:** `MGR_DEF` now lists every feature in `FEATS` (timesheets, approvals, rota, tasks, timeoff, reports, payslips, people, ai, settings). A manager starts with everything the owner has, and the owner switches off individual features per person in Settings > Users > open the person > Features. Before, managers lacked Payslips & P45s, People and Settings by default.
- Anything saved earlier in a manager's `feats` still wins. Labour cost stays owners/admins only. Company > Permissions toggles (mgrEditProfiles etc.) still apply on top.
- In the seed data only Director is Owner; everyone else (including Duygu) is Staff. To make Duygu a manager: Settings > Users > Duygu > Role > Manager.

## Payslips and P45s
- **Storage limit (told the owner, 10:21):** the 400 KB per-file limit is my choice. The real ceiling is the browser's storage: about 4.75 million characters per origin, shared by ALL app data. A payslip file takes about 4/3 of its size (base64). About 60 typical payslips would fill a phone's storage. Saving then fails and the chip shows "Not saved".
- **Owner decision (10:32, by voice):** stay browser-only for now, tell the manager the limit up front, see real file sizes, and move payslips to server-side per-person storage (with personal PINs) later if needed. Privacy warning: in shared server mode every phone downloads every file unless the private-login build (doc 03) is used.
- **Bulk upload (10:35), `src/52-bulkpay.js`:** Settings > Payslips (later inside Documents) has "Upload many" and "Upload one". Upload many: choose type (Payslips/P45s), a period or tax year typed once, and many PDFs or photos. A check screen lists each file with a tick, a person drop-down and status chips: Matched, Matched by first name, Check this one, Pick the person, No match, Remembered, Chosen, Too large, Not a PDF or photo, "Already has one for this period", "Another file for X". Nothing is sent until "Send selected". Each person gets a notification. Storage use is checked before sending (refuses past 97%), and a warning appears from 70% full.
- **Matching rules (`payMatch`):** file name lowercased, accents and Turkish letters flattened, split into words; months, "payslip", "p45", years ignored. Order of checks: remembered file-name key (`S.payMap`); payroll number (`p.payNo`); full name or "payslip name" alias with every word present in any order (score 100); first/only name (70, only if no tie); part of a name or a one-letter typo on words of 5+ letters (40/30, "Check this one"); ties are left for the manager. People > edit has "Payslip name (if different)" (`p.payName`) and "Payroll number (optional)" (`p.payNo`).
- Not built: reading the period from the file name, reading PDF contents, email in, per-person server storage.
